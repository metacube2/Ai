## 4. Woran Dynamics 365 Sales erkennbar ist

- Tabellen: `account`, `lead`, `opportunity`, `opportunityproduct`, `activitypointer`, `systemuser` (zusammen 1155 Spalten).
- Spalten nur in Dynamics 365 Sales: `msdyn_forecastcategory`, `msdyn_opportunityscore`, `msdyn_leadscore`.
- Muster des Dataverse-Connectors: zu jedem Code eine Namensspalte (`statecodename`, `owneridyominame`), zu jedem
  Betrag eine `_base`-Spalte.
- Keine ERP-Tabellen (Rechnungen, Artikelposten, Sachkonten).
- Eigene Felder mit Praefix `ava_` (Trafag-Anpassungen, vermutlich vom Einfuehrungspartner).

## 7. Idee: lesende Anbindung ans Dashboard

**Empfohlen: Dataverse Web API (OData v4) mit technischem Benutzer.**

1. IT (Alex) legt im Entra ID eine App-Registrierung an (Zertifikat oder Secret).
2. Dynamics-Admin legt einen Anwendungsbenutzer an, mit eigener Sicherheitsrolle **nur Lesen** auf `account`,
   `opportunity`, `opportunityproduct` (eventuell `lead`). Schreiben ist damit unabhaengig vom Code ausgeschlossen.
3. Das Dashboard holt die Daten in einem Hintergrundlauf (nachts) in SQLite, danach nur Aenderungen ueber
   `modifiedon`, wie beim Einkauf-Delta. In .NET mit `Microsoft.PowerPlatform.Dataverse.Client` oder HttpClient + MSAL.
4. Netzwerk: Server braucht ausgehend HTTPS auf `*.dynamics.com` und `login.microsoftonline.com`.

Anwendungsbenutzer brauchen keine Lizenz; die Abfragegrenzen von Microsoft sind fuer einen naechtlichen Lauf kein Thema.

| Anderer Weg | Warum nicht |
| --- | --- |
| Power-BI-Modell von Johannes anzapfen | persoenlicher Arbeitsbereich, seit Juli nicht aktualisiert, haengt an einer Person |
| Fabric Link / Synapse Link | kostenpflichtige Kapazitaet, fuer die Datenmenge zu viel |
| SQL-Endpunkt von Dataverse (TDS) | von sich aus nur lesend, muss aber eingeschaltet werden; ob er mit technischem Benutzer geht, ungeprueft |

**Nutzen:** Ueber `ava_sapid` CRM-Kunden mit SAP-Umsatz verbinden: Pipeline neben Ist-Umsatz je Kunde,
Gewinnquote je Produktfamilie, Kunden mit Umsatz ohne Verkaufschance.

**Aufwand:** etwa zwei bis drei Tage, sobald der Zugang steht (Abfrage, Tabellen, Hintergrundlauf, erste Seite).
